# Inbox Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** A live, local inbox of my workstreams (Linear ticket → PRs → agent events), open in a
pinned cmux workspace. Design: `docs/plans/2026-11-27-inbox-design.md`.

**Architecture:** One stdlib Python server (`bin/inbox-server.py`) under launchd keeps SQLite
current from `gh`, the watchers' state files and a Linear export. It serves a single HTML page
that re-renders over server-sent events. `bin/inbox` is the CLI for agents and for opening the
page in cmux.

**Tech Stack:** Homebrew Python 3 (stdlib: `http.server`, `sqlite3`, `threading`), `gh`
GraphQL, vanilla JS, cmux CLI, launchd.

**Verification:** no unit tests for now (by request). Each stage ends with a live check
against real data.

**Where to work:** branch `inbox` in the worktree `~/repos/automations-inbox`. Never run
`install.sh` from the worktree: it would point the live symlinks at the branch. Run the server
by hand from the worktree with `INBOX_PORT=8766 INBOX_DB=/tmp/...`. Merge to `main` at the
end of each stage, then run `install.sh` from `~/repos/automations`.

## Stage 1: Server, store, `gh` collector, read-only page

### Task 1.1: Server skeleton and schema

**Files:** create `bin/inbox-server.py` (executable, `#!/opt/homebrew/bin/python3`).

- Config from env: `INBOX_PORT` (default 8765), `INBOX_DB` (default
  `~/.local/state/inbox/inbox.db`). Assets resolve from the script's real path
  (`Path(__file__).resolve().parents[1] / "share/inbox"`), so a worktree run serves the
  worktree's page.
- `connect()`: WAL mode, `busy_timeout=5000`, `row_factory=sqlite3.Row`.
- Tables: `workstreams(key PK, title, linear_status, linear_url, snoozed_until, archived,
  updated_at)`, `prs(ref PK "repo#num", repo_full, num, workstream, title, url, state,
  is_draft, ci, review_decision, unresolved, additions, deletions, head_oid, updated_at,
  merged_at)`, `reviews(ref PK, repo_full, num, title, url, author, created_at, additions,
  deletions)`, `events(id PK, workstream, pr_ref, source, text, created_at, read)`,
  `meta(key PK, value)` for freshness and errors.

### Task 1.2: `gh` collector

- One GraphQL call per poll with three aliased searches: my open PRs, my PRs merged in the
  last 14 days, and open PRs with `user-review-requested:<login>`.
- Ticket key from the title: `^\[?([A-Z][A-Z0-9]*-\d+)\]?`. `PERS-TBD` or no match gives
  `pr:<repo>#<num>`.
- Upsert `prs` and `workstreams`. A workstream's title is its newest PR's title without the
  ticket prefix, until Linear supplies one.
- Diff each PR against its previous row and insert events: CI changed, review decision
  changed, unresolved threads went up, merged, opened.
- On failure, keep the old rows and set `meta.gh_error` and `meta.gh_error_since`. On a rate
  limit, sleep until `resetAt`. On success, set `meta.gh_synced_at` and clear the error.
- A thread polls every 120 s, plus once at startup.

### Task 1.3: HTTP endpoints

- `GET /`: `share/inbox/index.html`.
- `GET /api/state`: JSON with workstreams (each with its PRs and latest events), reviews and
  meta. Each workstream gets a `bucket`: `needs_you` if any open PR has CI `FAILURE`/`ERROR`,
  `CHANGES_REQUESTED` or unresolved threads; `done` if every PR is merged; `draft` if every
  open PR is a draft; otherwise `waiting`. Done workstreams older than 3 days are left out.
- `GET /events`: SSE. Each client gets its own connection and polls `PRAGMA data_version`
  every second, sending `event: changed` when it moves (catching commits from the collector
  thread and, from stage 2, the CLI). A comment heartbeat every 15 s.
- `ThreadingHTTPServer` bound to `127.0.0.1`. Reject any `Host` other than `localhost:<port>`
  or `127.0.0.1:<port>` with a 403.

### Task 1.4: Page

**Files:** create `share/inbox/index.html`.

- Top strip: counts per bucket, review count, GitHub freshness or error.
- Sections in order: Needs you, Review requests, Waiting, Drafts, Done. Workstream cards hold
  PR rows (repo short name, `#num`, state, CI dot, review decision, unresolved threads) and the
  latest 3 events.
- `EventSource('/events')` triggers a refetch and re-render that keeps scroll position and
  the set of expanded cards. A "reconnecting…" banner shows on `onerror`.
- Theme tokens in `:root`, with a dark variant under `prefers-color-scheme`. Everything
  escaped through `textContent`.

### Task 1.5: `bin/inbox open` and the launchd agent

**Files:** create `bin/inbox` (bash, `{ ...; exit; }` wrapped) and
`launchd/com.conordowling.inbox-server.plist.in` (`KeepAlive`, `RunAtLoad`, log
`~/.local/state/inbox/server.log`).

- `inbox open [--port N]`: if a workspace named `📥 Inbox` exists, select it; otherwise create
  it with one browser pane on `http://localhost:<port>/` and pin it.

### Task 1.6: Live check, then merge

1. `INBOX_PORT=8766 INBOX_DB=/tmp/inbox-dev.db bin/inbox-server.py` in the worktree.
2. `curl -s localhost:8766/api/state | jq '.workstreams | length'` is non-zero, and the
   PERS-TBD PRs appear as their own workstreams.
3. `curl -s -H 'Host: evil.com' -o /dev/null -w '%{http_code}' localhost:8766/` gives 403.
4. Open `localhost:8766` in a cmux browser pane. With the page open, run
   `sqlite3 /tmp/inbox-dev.db "insert into events(...)"`; the event appears without a reload.
5. Commit, merge to `main`, push, `install.sh`, `inbox open`.

## Stage 2: Watcher state and `inbox post`

- `bin/inbox post <ticket|repo#num> "<text>" [--source S] [--notify]`: resolve `repo#num`
  through `prs.workstream`, falling back to the title-prefix rule via `gh pr view`. Insert into
  `events` with `python3 -c` and sqlite3 (no server needed). `--notify` also calls `cmux
  notify` and `osascript`.
- Watcher-state collector (every 30 s): per PR, read `~/.local/state/pr-*-watcher/workspaces/<key>`
  for workspace ids, and check the fixer worktree for commits ahead of `prs.head_oid`. Set
  `prs.fixer_state` (`ready_to_push`, `dirty`, `idle`) and emit an event when it changes.
- Watchers: call `inbox post` when a session is opened, the fixer is dispatched, and cleanup
  closes or keeps something.
- Prompts: append "When you finish, run `inbox post <ref> '<one-line result>' --source
  <name>`" to the self-review, fixer and review prompts.
- Live check: post from the CLI with the page open; trigger a fixer dispatch and watch its
  events arrive.

## Stage 3: Actions

- Token: generated at first start into `~/.local/state/inbox/token` (mode 600) and injected
  into the served page. Every `POST` needs `X-Inbox-Token` and an allowed `Origin`/`Host`.
- `POST /api/focus` (`cmux` select the saved workspace id), `/api/open` (open a URL in the
  inbox's browser pane), `/api/start` (`self-review` or `fixer` for one PR: refactor the
  watcher scripts so one PR can be dispatched with `--only <ref>`), `/api/read`,
  `/api/snooze`, `/api/archive`.
- Live check: each button against a real PR; a `POST` without a token gets 403.

## Stage 4: Linear sync

- `bin/inbox-linear-sync.sh`: skip if idle for 15+ min (same check as `daily-rhythm-watcher`);
  run `claude -p` with a prompt asking for my assigned non-canceled issues, plus any issue a
  tracked PR's ticket key names, with status, URL, title, attachments (PR URLs) and comments
  since the last sync, written as JSON to `~/.local/state/inbox/linear.json.tmp`, then
  renamed.
- A launchd agent every 30 min; `POST /api/refresh-linear` runs it on demand.
- Server import: validate the shape, then set the workstream title, status and URL, re-link
  PRs by attachment (attachments beat the title prefix), emit events for status changes and
  new comments, and set `meta.linear_synced_at` and `linear_error`.
- Live check: run the sync by hand; the PERS-3233 workstream shows its Linear status and all
  4 PRs, including `app#169054`.
